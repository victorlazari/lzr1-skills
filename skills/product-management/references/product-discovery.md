## 1. Discovery Process

### Dual-Track Agile Workflow

1. **Discovery Track (what to build):** Research → Ideate → Prototype → Test → Validate
2. **Delivery Track (how to build):** Spec → Design → Develop → Test → Ship
3. Ensure Discovery feeds validated ideas into Delivery.

### Assumption Mapping Procedure

1. Identify assumptions across Desirability, Viability, Feasibility, Usability, and Ethical categories.
2. Rank assumptions by risk level (High, Medium, Low).
3. Prioritize testing High-risk assumptions first.

## 2. Problem Validation

### Problem Interview Structure

1. **Context:** Tell me about your role and how you handle [topic]
2. **Problem:** What's the hardest part about [activity]?
3. **Current solution:** How do you solve this today?
4. **Pain:** What frustrates you about current solutions?
5. **Impact:** How does this problem affect your work/life?
6. **Willingness:** What would you pay/do to solve this?

### Problem Validation Signals

| Signal | Strong Evidence | Weak Evidence |
|---|---|---|
| Frequency | "Every day" / "Multiple times a week" | "Once in a while" |
| Severity | "Costs us $X" / "Blocks our work" | "Mildly annoying" |
| Current solutions | Cobbled-together workarounds | "We just deal with it" |
| Willingness to pay | "I'd pay $X right now" | "Maybe if it were free" |
| Active searching | Already looking for solutions | Never searched |
| Emotional intensity | Frustration, strong language | Indifference |

## 3. Solution Validation

### Validation Methods

| Method | What It Tests | Sample Size |
|---|---|---|
| Usability test | Can users use it? | 5-7 |
| Fake door test | Do users want it? | 100+ clicks |
| Concierge MVP | Will users pay? | 5-10 customers |
| Landing page test | Is there demand? | 100+ visitors |
| A/B test | Which is better? | Statistical significance |
| Pilot/Beta | Does it work at scale? | 50-500 users |

## 4. Customer Development

### Product-Market Fit Indicators

| Indicator | Weak PMF | Strong PMF |
|---|---|---|
| Retention | Declining over time | Flat or improving |
| NPS | Below 30 | Above 50 |
| Word of mouth | None | Primary growth driver |
| Sean Ellis test | <40% "very disappointed" | >40% "very disappointed" |
| Sales cycle | Long, requires convincing | Short, pull from customers |
| Churn | High (>5% monthly) | Low (<2% monthly) |

## 5. Jobs to Be Done

### JTBD Framework

```
When [situation/trigger],
I want to [motivation/job],
So I can [expected outcome].
```

### Outcome-Driven Innovation

```
Direction of improvement + Metric + Context

Example outcomes:
- "Minimize the time it takes to find relevant search results"
- "Minimize the likelihood of missing an important notification"
- "Increase the accuracy of budget forecasts"
```
